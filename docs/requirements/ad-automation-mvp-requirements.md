# 广告素材自动化处理系统 MVP 需求

## 1. 目标

提供一个可在本机启动的演示系统，验证“素材上传 → 视频处理 → 状态监控 → 模拟投放平台同步 → SPI 回调 → 异常告警”的完整链路。

## 2. 用户与场景

主要用户是投放运营和素材制作人员。用户能够上传视频，查看素材元数据和重复标记，选择处理步骤生成新版本，查看任务进度，将产物同步到模拟平台，并通过回调模拟审核结果和异常。

## 3. 功能需求（MVP 边界）

以下为本地演示已实现范围；巨量引擎、快手真实接口需要官方文档和测试凭证，不在本版本承诺内。

### 3.1 素材管理

- 支持 MP4、MOV、WEBM 视频上传；默认单文件上限 500 MB。
- 保存原始文件名、媒体类型、大小、时长、分辨率、SHA-256、感知指纹、创建时间和当前状态。
- SHA-256 完全相同的文件标记为 `duplicate`，保留文件，不自动删除。
- 提供素材列表、详情和产物关联查询。

### 3.2 视频处理

- 通过任务创建接口提交一个素材和有序步骤列表。
- MVP 步骤：裁切、片段拼接、角标/字幕、编码参数、可选画质增强参数。
- 任务状态：`pending`、`running`、`succeeded`、`failed`、`dead_letter`。
- 记录每一步参数、FFmpeg 命令摘要、耗时、输出文件和错误原因。
- 失败任务可重试，最多 3 次；重试保留原失败事件。

### 3.3 平台同步

- 提供统一平台适配器接口和 `mock` 实现。
- 上传后保存平台名称、远端素材 ID、远端状态和最近同步时间。
- 支持状态查询和手动同步；模拟平台支持待审核、通过、拒绝状态，重复同步保持幂等。
- 巨量引擎和快手真实接入只在取得官方文档和测试凭证后实现，不在 MVP 中猜测字段。

### 3.4 SPI 回调

- `POST /api/spi/{platform}` 接收 JSON 回调。
- 使用配置的 HMAC 密钥验证签名；签名错误返回 401 并创建告警。
- 使用平台事件 ID 幂等；重复事件返回 200，不重复写状态变更。
- 保存脱敏后的原始 payload、事件时间和归一化后的内部事件。

### 3.5 异常告警

- 对处理失败、平台拒绝和回调签名错误创建告警；同步超时和重试耗尽列入后续告警规则。
- 告警包含级别、来源、关联对象、摘要、详情、首次发生时间和确认状态。
- 支持告警列表和确认操作；确认不删除事件日志。

### 3.6 控制台

- 提供素材、处理任务、平台状态、异常中心四个页面或对应视图。
- 页面显示加载、空状态、失败状态和任务刷新状态。
- MVP 不做登录、权限和多租户；仅用于本机演示。

## 4. 非功能需求

- Windows 本地可运行，依赖 Python 3.11+、FastAPI、SQLite、FFmpeg/ffprobe。
- 所有本地运行数据放在 `ad_automation_data/`，不得提交到 Git。
- 环境变量和密钥不写入仓库；提供 `.env.example` 时只能包含占位值。
- API 错误返回结构化 JSON；外部调用设置超时和有限重试。
- 关键操作写结构化事件日志，敏感值脱敏。

## 5. MVP 验收标准

1. 能启动服务并通过健康检查。
2. 上传一个短视频后可查到 SHA-256、媒体元数据和文件路径。
3. 创建处理任务后能生成至少一个可播放产物，并显示任务日志。
4. 相同文件再次上传会被标记为重复。
5. 产物可同步到 mock 平台，状态可通过查询或 SPI 回调改变。
6. 无效签名和失败任务会产生告警，告警可确认。
7. `pytest` 测试通过，仓库没有上传素材、数据库、密钥和运行缓存。
